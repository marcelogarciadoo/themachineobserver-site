# Prompt for the scheduled routine “Atualizar pesquisas — themachineobserver.com (v3)”

You maintain the raw polling data for `https://themachineobserver.com`. The repository `marcelogarciadoo/themachineobserver-site` is checked out in your working directory and pushing to `main` is authorized. Do not edit site code or model outputs.

The live redesign reads `data/raw-polls.json`. The legacy `data/polls.json` must remain synchronized for compatibility. New raw polls are editorial evidence; adjusted estimates and Monte Carlo results are rebuilt and released separately after validation.

1. Build pending registrations from the TSE registry mirror at `https://raw.githubusercontent.com/rafaujo/eleicoes-2026-pesquisas/main/data/tse-metadata.json`. Normalize protocols as `BR-NNNNN/YYYY`. A registration is pending when it appears in neither the second-round records nor the legacy `ignored` list and its disclosure date is today or earlier in `America/Sao_Paulo`.
2. Check at most eight pending registrations per run, newest first. Prefer the institute report or contracting outlet. Search the institute's official site and original report/PDF first, then the commissioning outlet/publisher. Credible secondary journalism can also support a clearly marked provisional-source result when it explicitly publishes the national total-respondent figures and sufficient survey metadata. Never guess or infer voting shares from a registry alone. If the mirror JSON is stale, consult the current TSE CSV or official registry; unavailable data is not evidence that no polls exist.
3. Confirm institute, national presidential scope, field dates, sample size and registration. Record any explicit discrepancy in `auditNote` instead of silently changing the registered metadata.
4. Extract each actually published relevant round independently, including the Lula × Flávio Bolsonaro runoff over total respondents. Do not invent a first-round companion for runoff-only polling. Preserve blank/null/no-vote, undecided and grouped-other categories when published. Record missing categories as missing, never zero. Store the stated margin of error, confidence and method when available, the exact publishing source URL, and the primary report when located. Secondary-source records use verification: provisional-source and an auditNote beginning 'PROVISIONAL —', explicitly documenting which primary-source checks remain outstanding. Upgrade provisional records using the original institute report when available, preserving the stable ID and verified metadata; never silently overwrite discrepancies.
5. Append the documented round-1 and/or round-2 records to `data/raw-polls.json` using the actual shapes supported by `automation/ingest_poll_update.py`, preserving its schema. IDs must be unique and monotonically extend the existing `RAW-R1-###` and `RAW-R2-###` series. When both rounds exist, they must share the normalized registration and source metadata. Each round's stable `waveId` ends in `|R1` or `|R2`. Keep records ordered by publication date, then ID.
6. Append the same verified or appropriately labeled provisional runoff result to legacy `data/polls.json`. Ignore a protocol only with evidence that it is outside national presidential scope or definitively has no relevant runoff result, giving a short evidenced reason. If no published figures can be substantiated, leave the protocol pending, not ignored. Revisit provisional records for primary-report upgrades.
7. Set both artifacts’ update timestamps to today. Validate JSON, unique IDs, dates (`start <= end <= published`), percentages in 0–100, and consistency of each supplied round; runoff-only and first-round-only records are allowed by the current ingestion validator. Confirm the new records are present before committing.
8. When polling feeds changed, run `automation/ingest_poll_update.py` with an audited payload and `--check-only`, then commit only `data/polls.json` and `data/raw-polls.json` with `polls: <institute(s)> <YYYY-MM-DD>` and push `main`. The raw-feed change triggers the complete gated recalculation. Hostinger receives the redesign's raw data, adjusted estimates, simulation and pages together only after that workflow passes; the preserved legacy page continues to receive `data/polls.json` independently.

Finish with: rows added/upgraded and sources (identifying provisional status); protocols ignored with evidence; protocols still pending and why; validator and exact-SHA workflow status; whether production/Hostinger actually reflects the release. Do not mistake an updated GitHub production branch marked `research_only` for an approved live deployment. If nothing changed, say so. Never publish a statistical correction or alter an adjusted/model release in this routine.
